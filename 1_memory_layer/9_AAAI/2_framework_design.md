# Personal Fact Memory (PFM)：学术化框架设计

把 `5_dpfm`/`8_dpfm_application` 的工程系统 DPFM（Dual-Path Fact Memory）
重述为一个可投稿的研究范式。**DPFM 是 PFM 范式的一个具体实例**——已实现
的部分直接引用现有实测数据，未实现的部分（§4）是论文投主赛道时最值得
补的新内容。

## 1. 问题形式化

给定单一用户 $u$、随时间增长的个人语料 $D_u$（用户写过/收过的消息、
邮件、笔记，源源不断以文档流形式到达）、以及一次生成请求的上下文 $c$ 与
延迟预算 $\Delta$（由宿主 LLM 自身的 prefill/网络延迟决定，量级通常
10–50ms），检索出一个有界事实集合 $F \subset \mathrm{Facts}(D_u)$，
$|F| = k$，使得：

- **(a) 身份接地（identity grounding）**：$F$ 中每条事实携带其在 $D_u$
  中的实体归属与参与者归属，检索打分对"上下文提到的人/实体"和"泛文本
  相似度"做差异化加权，使得同形句子在不同身份语境下被正确区分/关联。
- **(b) 截止时间安全（deadline safety）**：检索在 $\Delta$ 内以高概率完成，
  且完成时间**不随 $|D_u|$ 增长而退化超过对数/次线性量级**——因为个人语料
  会无限增长，若检索延迟线性于语料规模，系统会随使用时间推移变慢。
- **(c) 有界存储（bounded footprint）**：$|\mathrm{Facts}(D_u)|$ 有界，
  由一个不依赖人工排期、随使用模式自适应的遗忘策略维持，同时保证高价值
  事实（如用户身份属性）永不被误删。
- **(d) 自我修正（self-correction）**：对同一"槽位"（如"下次会议时间"）
  的矛盾更新自动以最新版本覆盖旧版本，覆盖后的旧事实保留审计轨迹但不参与
  检索排序，避免矛盾事实同时出现在注入给 LLM 的 prompt 里。

## 2. 三大支柱

### P1 — 身份接地关联（Identity-Grounded Association）

**原子事实表示**：$f = (\text{text}, \text{entities}, \text{participants},
\text{kind} \in \{\text{episodic}, \text{semantic}, \text{profile}\},
\text{key}, t_{\text{valid\_from}}, t_{\text{invalid\_at}})$。

**字段加权词法索引**：检索用 simple-BM25F（Robertson & Zaragoza 2009 §3.5;
Robertson et al. 2004），字段权重 text : entities : participants =
1.0 : 2.5 : 2.0——个人补全场景需要**逐字拷贝**姓名/日期/数字，词法精确匹配
比语义相似度更对口；参与者字段加权识别"这段对话/这封邮件是写给谁的"，是
判定一条历史事实是否与当前上下文相关的强信号，而非通用语义检索会用到的
特征。

**双时态槽位覆盖**：新事实与旧事实共享同一个 `key`（如
`('phoenix', 'deadline')`）时，旧事实被标记 `invalid_at`（借鉴
Zep/Graphiti 的双时态边，arXiv:2501.13956），从索引中移除但不物理删除——
既满足 (d) 自我修正，又保留可审计性。

**关联式召回**：实体共现图 + 截断一跳扩散激活，是 HippoRAG
（arXiv:2405.14831）Personalized PageRank 的轻量近似，用于"上下文没有
显式提到，但和已识别实体强关联"的召回（如提到 Alice 时联想到她负责的
Phoenix 项目）——区别于 HippoRAG 原论文以查询词为种子做面向开放域 QA 的
个性化，这里的种子始终来自**同一用户**的身份图谱，图谱本身就是个人化的。

### P2 — 有界延迟安全服务（Bounded-Footprint, Deadline-Safe Serving）

**冷热路径分离**：写路径（抽取、去重、图更新、剪枝）异步、无延迟上限；
读路径纯内存操作（dict/heap），预算化到 ≤12 个查询词（WAND 式剪枝，按
`weight × idf` 排序截断），posting list 长度由个人语料规模（$10^3$–$10^5$）
界定，不接入向量库/ANN/LLM 调用。

**非阻塞保证**（形式化表述）：两种机制协同给出最坏情况的上界：

1. **推测预取（speculative prefetch）**：后台线程在输入停顿时触发检索，
   写入不可变快照；生成请求触发时只做一次属性读取。
2. **截止时间竞速（deadline race）**：新检索与生成请求的自身延迟预算
   $\Delta$ 并发起跑，超时回退到最近快照（标记 stale）。

两者结合给出：**加到生成路径上的最坏延迟 = min(一次属性读取, $\Delta$)**——
即无论语料多大、检索器多慢，都不会让宿主 LLM 的响应变慢超过用户设定的
预算。这是一个可以在论文里正式写成命题并证明的性质（目前 DPFM 的实现
已满足，但 `5_dpfm/README.md`/`DPFM-EXPERIMENT-REPORT.md` 只报告了实测
延迟数字，没有把非阻塞性写成可证明的命题——写论文时应该补上）。

**有界遗忘**：周期性剪枝移除 $\mathrm{recency}(f) \times (1 + \mathrm{heat}(f))$
低于阈值的事实（profile 类事实除外），使语料规模由使用模式（哪些事实被
持续引用/强化）而非原始文档量线性决定。

### P3 — 生物学启发的分层（Biologically-Grounded Stratification）

**三种事实类型对应三种记忆系统**（互补学习系统理论，McClelland,
McNaughton & O'Reilly 1995）：

| kind | 类比 | 特性 |
|---|---|---|
| episodic | 海马体快速编码 | 绑定单一源文档，随时间/使用衰减 |
| semantic | 新皮层慢速语义化 | 跨文档反复观察后沉淀，衰减更慢 |
| profile | 核心自我图式 | 永久固定（pinned），不参与遗忘 |

**双衰减打分**：

$$\mathrm{score}(f) = \mathrm{BM25F}(q,f) \cdot
\Big(\varepsilon + (1-\varepsilon)\cdot 2^{-\Delta t/T_{\mathrm{rec}}}\Big)
\cdot \big(1 + \eta \cdot \mathrm{heat}(f)\big) + \gamma \cdot \mathrm{assoc}(f)$$

- **recency 项**：指数衰减 + 非零下限 $\varepsilon$——对应 Ebbinghaus
  (1885) 遗忘曲线，下限对应心理学中"节省效应"（旧记忆虽提取困难，一旦
  强匹配线索出现仍可被唤起，重新学习比首次学习快）。
- **heat 项**：使用强化的衰减计数器，用户接受补全时触发（`mark_used`）
  ——对应间隔重复/测试效应（testing effect, Roediger & Karpicke 2006）：
  提取行为本身强化记忆痕迹，而不仅仅是"再看一遍"。这形成一个闭环：
  被检索且被采纳的事实获得更高的未来检索优先级，模拟"越用越牢"的巩固
  过程。

**与 Human-Inspired Memory Architecture 的关键区别**：该系统的"engram
成熟"和"再巩固"机制需要**跨 session 的重复访问信号**才能触发，作者自己
承认在 LongMemEval 这类基准上"记忆从不积累重复访问信号"，因而这两个机制
未经实证验证。**个人助手场景恰好天然提供这个信号**——同一用户会反复
在相似语境下触发补全、反复接受/拒绝——DPFM 的 heat 机制本质上就是这个
未被验证的"再巩固"假说的一个可运行、已实测的简化版本，这是论文可以明确
拿来对话的点。

## 3. Pipeline

```
                        ┌─────────────── 冷路径（异步，无延迟上限）───────────────┐
   已发送/已保存文档 ──▶ │ 抽取(规则/LLM可插拔) → 去重(Jaccard) → 槽位覆盖(bi-temporal) │
                        │        → BM25F 倒排索引 + 实体共现图更新 → 周期剪枝        │
                        └──────────────────────────┬───────────────────────────┘
                                                     │ 索引/图（内存，个人语料规模）
   ┌──────────────── 热路径（同步，Δ 预算内）─────────────────┐
   │ 输入上下文/参与者 → 焦点词查询构造(位置衰减+参与者加权+IDF剪枝) │
   │   → BM25F top-k × recency × heat + 实体图联想(assoc)      │
   │   → RRF 融合可选 embedding backup → prompt block          │
   └───────────────────────────┬───────────────────────────┘
                                │
          ┌─────────────────────┴─────────────────────┐
          │ 推测预取快照(zero-wait)  或  截止时间竞速(≤Δ)  │──▶ 注入 LLM prompt
          └───────────────────────────────────────────┘
                                │
                    用户接受/拒绝补全 → mark_used(fact_ids) ──▶ 反哺 heat（闭环）
```

## 4. 提议的新贡献：把 prompt 注入建模为选品问题（未实现，投主赛道前最值得补）

现状有两个缺口，分别对应一个运筹学工具：

1. **参数缺口**：$\varepsilon$（recency floor）、$\eta$（heat 权重）、
   $\gamma$（关联权重）、两个半衰期都是**全局常数**——"个性化"目前只
   体现在语料内容（每个用户有自己的事实库），不体现在检索公式本身的
   参数上。→ §4.1 用离散选择模型解决。
2. **决策缺口**：最终注入是 **top-k by score + 贪心截断**。在存在替代
   效应（substitution）的选择行为下，top-k 不是最优解：两条高分但近似
   冗余的事实互相蚕食，浪费一个槽位和一段字符预算，top-k 对此视而不见。
   → §4.2 用带约束选品优化解决。

### 4.1 需求侧：接受/拒绝 = 离散选择，在线 MLE 估计融合权重

`mark_used`（接受）与"注入但未被采纳"（隐式拒绝）天然构成离散选择观测：
选择集是 {接受补全, 拒绝(outside option)}，接受效用用打分公式的对数线性
参数化表示，$\{\varepsilon, \eta, \gamma, T_{\mathrm{rec}}, T_{\mathrm{heat}}\}$
成为 MNL / conditional logit（McFadden 1974）的效用系数，按用户在**冷路径**
做在线极大似然更新（对数似然的 SGD；反馈是稀疏 0/1 信号，单步开销可
忽略，不触碰热路径）。相比早前草案的 contextual bandit 措辞，这一步把
理论根基从"调参技巧"换成有 60 年计量经济学传统的模型族，且学出的参数
天然可解释：$\eta$ 偏高 = "复读机型"用户（依赖重复强化），$\gamma$ 偏高
= 联想召回依赖型——参数画像本身即"个体特异性"卖点的附加发现，而不只是
让准确率数字更好看。

**与 RCPO 的定位切割**（Tang & Feng, arXiv:2510.23631, ICLR 2026）：RCPO
把（排序）选择模型用于**训练侧**——推广 DPO/SimPO 的 alignment 目标
函数，改的是 LLM 权重；我们用于**服务侧**——LLM 完全冻结，选择模型是
选品优化的需求模型。共享的只是统计工具族；问题、数据（精标偏好数据集
vs. 真实使用中的隐式二元反馈）、被优化对象（数十亿权重 vs. 每用户 5 个
标量 + 一个组合决策）全部不同。写作时应主动引用并一句话钉死差异，而非
回避。

### 4.2 供给侧：k 槽位 + 字符预算 = 带约束 assortment optimization

形式化：

$$\max_{S \subseteq C} \; \Pr[\text{accept} \mid S] \quad
\text{s.t.} \quad |S| \le k, \;\; \sum_{f \in S} \mathrm{len}(f) \le B$$

其中 $C$ 为检索候选集，$k{=}6$，$B{=}800$ 字符。这正是收益管理文献的
经典问题结构：无约束 MNL 选品有 revenue-ordered assortment 最优结构
（Talluri & van Ryzin 2004），基数约束下有多项式最优算法
（Rusmevichientong et al. 2010 一脉），knapsack 型约束有 FPTAS
（Désir & Goyal 一脉）——**以上具体引文均标注在 references.bib 中且
投稿前必须核实**。在我们的规模（候选 ~40 条选 6 条）上，贪心或 DP 是
微秒级运算，可直接内联热路径，不破坏 P2 的非阻塞命题。

**效率主张的准确表述**：这一步提升的不是检索延迟（已比 LLM prefill 低
两个数量级，无利可图），而是 **prompt-token 效率**——同等接受率用更少
的注入字符达成，直接节省每次请求的 prefill 算力。对端侧小模型场景这是
真实的算力预算约束，与论文的部署故事自洽。

### 4.3 建模近似的诚实交代（审稿人会问）

经典选品问题里顾客**直接从货架挑商品**；我们的用户不直接挑事实——他们
接受/拒绝的是**下游补全**，事实的效用经过 LLM 中介（facts → completion
→ accept 的两段因果链）。严格说，我们是把接受概率当作事实集合的集函数、
借 MNL 结构去估计——"MNL over facts"是一个需要在论文里显式交代的近似
假设。处理得当，这反而是与 RCPO 和经典选品文献都不同的结构特征——
贡献点而非弱点。

### 4.4 评估设计（离线可行，7/28 前可完成，不需要真实用户）

复用 `DPFM-EXPERIMENT-REPORT.md` 的大规模 harness（270 facts / 25 场景），
模拟按用户偏好采样的接受/拒绝序列，三臂对比：

| 臂 | 融合参数 | 注入决策 |
|---|---|---|
| A（现状基线） | 全局常数 | top-k |
| B | 在线 MLE（§4.1） | top-k |
| C | 在线 MLE（§4.1） | assortment（§4.2，贪心/DP） |

指标：模拟接受概率、NDCG@k（参数收敛后的排序与模拟偏好的一致性）、
**注入字符数**（token 效率，C 臂的核心主张：同等接受率下更省）。

**循环论证风险与缓解**：用 MNL 模拟用户、又用 MNL 优化选品，结果必然
好看——审稿人一定会抓。缓解：**model-mismatch 鲁棒性检验**——用
mixed logit / nested logit 模拟"真实"用户，仍以 MNL 假设做估计与优化，
报告增益保留比例。这个检验本身是实验设计的亮点，而不只是防守动作。

## 6. 局限性（诚实呈现，审稿人会问）

1. 规则抽取器召回有限（已知：无信号动词的事实会被漏掉），是当前系统
   唯一的失败模式来源，`DPFM-EXPERIMENT-REPORT.md` 已量化。
2. Study 1 的 fact availability 是"prompt 侧代理指标"，不等于 LLM 真的
   用上了、用户真的采纳了——需要 Study 2 补齐端到端证据。
3. 语料是脚本化/半合成的（大规模 harness 含 240 条合成填充事实），真实
   用户消息噪声更高，结论的外部效度需要 Study 2 验证。
4. §4 的选择模型 + 选品优化提议目前只有设计，没有实现和实验——如果
   7/28 前来不及，诚实的选择是把它降级为"Future Work"小节而非核心贡献，
   主线论文仍可立足于 P1/P2/P3 + Study 1/2 成立。此外 §4.3 的两段因果链
   近似（用户接受的是下游补全而非事实本身）必须作为显式假设写进正文，
   不能藏在附录。
