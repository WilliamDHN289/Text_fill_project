# PFM: code and benchmark

Reference implementation of Personal Fact Memory (PFM), the synthetic update
benchmark, and the scripts behind every table and figure in the paper. All
data is generated by `benchmark.py`; nothing here reads personal or
user-derived text.

## Layout

| File | Role |
|---|---|
| `config.yaml` | Frozen method parameters (`pfm`) and every experiment setting |
| `pfm.py` | Store, BM25F index, entity graph, ranking, greedy selection, serving protocol |
| `identity.py` | Identity posterior over candidate entities; slot and margin abstention gates |
| `realdata.py` | LongMemEval and LoCoMo loaders, turned into the same `Bench` format |
| `extractor.py` | Rule extractor, keyed extractor, keyless control, key-noise injection |
| `benchmark.py` | Update benchmark generator and labels |
| `arms.py` | Retrieval arms (PFM, BM25 variants, MiniLM dense, RRF hybrid, identity baselines) |
| `metrics.py` | Per-query outcomes, slices, chain-cluster bootstrap, McNemar |
| `exp_*.py` | One experiment each (see below) |
| `make_report.py` | LaTeX tables, figures, `numbers.json`, judge audit sheet |
| `answer_w1.py` | The extractor ladder read as one table: key quality vs clean retrieval |
| `answer_w2.py` | The open-domain key diagnostics, coverage and merging reported apart |
| `tests/test_pfm.py` | Invariants: verbatim revision, pruning exemption, reader atomicity, fresh-mode fallback |

| Experiment | Paper artifact |
|---|---|
| `exp_temporal.py` | Table 1 (keyed vs keyless), benchmark accounting |
| `exp_baselines.py` | Table 2, Figure 1 (clean by deadline), paired tests |
| `exp_ablation.py` | Table 3 (leave-one-out), identity baselines |
| `exp_keynoise.py` | Figure 2 (missed / false merges) |
| `exp_llm.py` | Table 4 (response level, TTFT), retrieval latency during generation |
| `figstyle.py` | One visual system for every figure: palette, type sizes, legend placement |
| `exp_serving.py` | Appendix: lagged snapshots, latency under concurrent construction |
| `exp_scaling.py` | Appendix: store-size scaling |
| `exp_identity.py` | Identity posterior and abstention gates on the benchmark and its slices |
| `exp_real.py` | LongMemEval knowledge-update, LoCoMo misattribution and abstention |
| `exp_systems.py` | Query-time model baselines: temporal rerank, entity resolve, abstain judge |

## Running

```bash
pip install -r requirements.txt
sh data/fetch.sh                              # LongMemEval + LoCoMo; needed by exp_real
python3.11 tests/test_pfm.py
python3.11 run_all.py --smoke                 # a few minutes; checks the pipeline
python3.11 run_all.py --only temporal baselines ablation keynoise serving scaling
python3.11 run_all.py --only identity
python3.11 run_all.py --only llm real systems --out results/<same run>   # needs ollama + qwen2:7b
python3.11 make_report.py results/<run>
```

Each run directory holds per-query JSONL logs, per-experiment JSON, the
config actually used, and `env.json`. Tables are derived from the logs, so a
new column or slice never needs a re-run.

## Measurement notes

- Latency: `perf_counter` around rank + select + format, batch 1, one request at
  a time; each (query, repeat) times every arm in a new random order and every
  run is kept. MiniLM runs on CPU with the thread count in `config.yaml`;
  corpus embeddings are precomputed, query embeddings are not cached.
- The response-level study uses ollama with greedy decoding. Every prompt starts
  with a random request id so no cached prefix is reused and TTFT includes the
  full prefill. `llm.json` records the ollama version, quantization, and
  processor placement.
- Numbers are machine-specific; `env.json` records the machine.
- Intervals resample seeds and then chains inside each seed; a rate of exactly 0
  or 1 falls back to the Wilson interval over chains, so it reads as a bound.
  Paired tests flip the sign of a whole chain at a time; `metrics.tost` runs the
  two one-sided tests behind every equivalence claim.
- `exp_real.py`, `exp_extractor.py` and `exp_systems.py` cache every model call by
  (model, length, prompt) in the run directory, so the public-corpus results rebuild
  without a GPU and adding a model to a ladder re-runs only that model.
- `exp_extractor.py` sweeps `extractor.models` x `extractor.seeds`. The rewriter
  (`extractor.rewriter`) is held fixed across the sweep so every key assigner reads
  the same paraphrased text and the comparison is a paired difference on one corpus.
  `key_quality` reports the error taxonomy, not only precision and recall, because
  the ordering the paper claims turns on which way the keys are wrong.
- `exp_real.py` assigns open-domain keys two ways: stateless (one call per turn) and
  key-aware, where the extractor is shown the keys already in the store
  (`real.key_aware_candidates`) and may reuse one. The second is the condition under
  which a claim about open-domain supersession is about the mechanism rather than
  about a stateless extractor.
